# ZIP 소개 랜딩 전체 재설계

2026-11-12 · 기존 제작·배포 승인 이후 사용자가 범위를 바로잡은 후속 설계. 사용자 요청: 첫 화면부터 스토리텔링 자체를 재기획하고, 인터랙션·효과·동작이 연결되게 고도화한다. 제품 정의·ZIP 브랜드·가상 예시 범위는 기존 승인 설계를 따른다. 아래 문구·구도·구현 방식은 제작자의 판단이다.

## 목적과 현재 문제

방문자가 ‘이 장소의 조건에 이 가격이면 내게 괜찮은 선택인가?’라는 질문을 이해하고, ZIP이 조건을 모으고 중요도를 반영하고 가격과 비교하는 과정을 한 흐름으로 경험하게 한다. 현재 페이지는 비슷한 도시 세 개와 24개 시점 조작이 반복돼 모형이 서비스 가치보다 앞선다. 그 반복을 없애고 첫인상·문제·새 관점·체험·선택 이유의 흐름을 새로 만든다.

## 접근 선택

- 기능 목록형: 읽기는 쉽지만 왜 필요한지와 앞뒤 장면의 인과가 약하다.
- 영상 예고편형: 하나의 연출에는 좋지만 사용자의 기준이 실제 결과로 연결되는 체험과 자연스러운 탐색이 약하다.
- **같은 장소를 계속 읽는 이야기형 — 채택.** 한 도시와 동일한 장소 식별자를 유지하며 가격→조건→내 기준→가격 비교를 보여주고, 한 곳의 체험으로 이어진다. 기존 모형과 계산은 재사용하고 페이지 구성과 시각 위계, 동작 연결을 다시 만든다.

Taste v2: `split-stage`, seed `848239414`, palette/type 유지. 본인만의 소재: 가격을 점수에서 제외, 사용자 중요도, 청록 가격·보라 점수, 건물 선택, 세 곳 비교, 신고·추정·자료 없음의 구분. **ZIP에서 ‘같은 건물에 겹치는 서로 다른 정보’가 한 도시를 계속 읽는 장면 전환이 된다.** 첫 hero slot의 카페 줄무늬는 ZIP에 없는 장식이어서 1회 redraw했다. 새 menu-column geometry는 제품 UI를 보며 읽는 좌우 무대로 적용하며 가짜 영업시간·주소, 둥근 메뉴판·중앙 정렬 문구는 만들지 않는다. 브랜드·방향 규칙이 blueprint보다 우선한다.

## 페이지의 주장과 증거

| 방문자가 이해할 것 | 화면에서의 증거 |
|---|---|
| 가격만 알아서는 내게 맞는지 판단하기 어렵다 | 처음에는 같은 예시 장소의 가격표가 먼저 보임 |
| 장소에는 함께 읽어야 할 조건이 있다 | 같은 장소에 경사·고도·연식이 이어서 드러남 |
| 조건의 중요도는 내가 정한다 | 같은 건물이 가격 청록에서 내 기준 보라로 전환 |
| 조건을 맞춘 뒤 가격을 비교한다 | 선택 장소와 ±5점 예시의 실제 월 환산 단가를 나란히 표시 |
| 내 기준이 실제 결과를 바꾼다 | 한 집중 체험에서 슬라이더→모형 색→선택 요약→비교를 갱신 |
| 선택의 이유를 스스로 설명할 수 있다 | 담은 세 곳의 가격·점수·경사·연식을 먼저 비교, 상세 표는 펼쳐보기 |
| 근거와 한계를 함께 읽는다 | 개발 중, 가상 값, 신고/추정/묶음/결측의 구분 |

## 스토리보드와 확정 제작 문구

### 첫 장면 — 나의 질문

H1: **이곳, 이 가격이면 / 내게 괜찮을까?**
본문: **장소의 조건을 내 중요도로 모으고, 비슷한 조건의 장소와 가격을 비교하는 지도 플랫폼.**
행동: **내 기준으로 체험하기** → `#experience`.

읽는 문구와 큰 도시가 좌우 무대를 이룬다. 첫 화면에 여러 시점 버튼이나 전체 주제를 나열하지 않는다. 도시의 현재 장소, 보증금·월세와 가상 예시 표시는 HTML로 읽힌다. 스크롤 안내는 ‘아래로, 가격표 뒤의 조건을 보세요’다. 3D 로딩을 기다리는 화면이나 강제 오프닝은 없다.

### 가격 뒤의 조건

H2: **가격표 뒤에 / 다른 조건이 있습니다**
본문: **매일 오를 길, 건물이 지어진 때, 장소의 높이. 따로 보던 정보를 같은 장소 위에 놓습니다.**
같은 도시·같은 선택 장소에 경사·고도·연식이 드러난다. 지형 색은 경사 의미를 유지한다. 미래 교통·햇빛 등의 가짜 수치를 넣지 않는다.

### 나의 기준

H2: **중요한 조건부터 / 도시가 달라집니다**
본문: **완만한 길이 먼저인 사람도, 새로운 건물이 먼저인 사람도 있으니까. ZIP의 기준은 내가 정합니다.**
같은 도시가 보라색 점수로 바뀌고 선택 장소의 점수가 보인다. ‘가격은 점수에 넣지 않습니다’를 바로 읽을 수 있다. 스크롤은 사용자의 중요도나 담은 장소를 변경하지 않는다.

### 조건 옆의 가격

H2: **비슷한 조건이라면 / 가격은 어떨까요**
본문: **조건이 비슷한 장소끼리, 실제로 어떤 가격 차이가 있는지 나란히 봅니다.**
선택 장소의 월 환산 단가와 현재 기준 ±5점인 예시를 표시한다. 비교 표본 5곳 미만이면 퍼센트를 만들지 않는다. 건물은 가격 청록으로 돌아와 점수와 가격의 서로 다른 의미를 설명한다. 자세한 계산은 체험의 ‘가격을 읽는 방법’에서 확인한다.

### 집중 체험 — 내가 바꾸는 장면

H2: **이번에는 / 당신의 기준으로**
본문: **가장 중요한 조건의 막대를 움직여보세요. 도시의 색과 선택한 장소, 아래 비교가 함께 바뀝니다.**
한 개의 3D 모형과 세 슬라이더. 지도 주제는 가격/내 기준/가격 대비/지형. 기본 체험은 내 기준이며 공유 URL의 명시적 mode는 존중한다. 슬라이더를 직접 움직이면 내 기준으로 전환해 재색칠을 바로 확인한다. 시점 조절은 이 체험의 펼침 영역 한 곳에만 제공한다. 예시 A/B/C는 처음부터 비교에 담겨 있고 그 사실을 안내한다. 추가 장소 선택은 전체 보기와 지도 클릭으로 가능하다.

### 선택 이유

H2: **정답 대신, / 선택할 이유를**
본문: **가격과 조건을 나란히 놓으면, 무엇을 얻고 무엇을 감수할지 보입니다.**
담은 장소를 큰 실제 이름표와 가격·점수·경사·연식 요약으로 비교한다. 담기·빼기·선택 강조가 같은 ID를 사용한다. 상세 비교표는 native details 안에 두고 필요한 사람이 펼친다. 표가 닫혀 있어도 주요 실제 값은 읽힌다. 담은 장소가 0개이면 빈 상태와 체험으로 돌아가는 행동을 제공한다.

### 근거와 마무리

H2: **보이는 숫자에 / 근거를 남깁니다**
신고 계약, 추정 조건, 비슷한 건물 묶음, 자료 없음의 차이를 짧은 읽기 문구로 설명한다. FAQ 세 질문은 지금 이용 가능 여부/현재 매물 여부/첫 범위다. 첫 범위 관악의 가격·건물·지형, 나머지는 계획이라는 구분을 유지한다.

마무리: **가격표를 넘어, / 나의 선택으로.**
본문: **중요한 조건을 정하고, 장소를 다시 읽어보세요.**
행동: **내 기준으로 체험하기** → 같은 체험으로 복귀. 거대한 반복 워드마크 대신 간결한 출처·개발 중 표시·GitHub 링크로 닫는다.

## 연결된 동작 계약

1. 소개 구간은 한 `#story-city`를 유지한다. DOM 모형을 매 섹션마다 새로 만들지 않는다. 읽는 장의 진행에 따라 phase와 색 의미가 price→terrain→score→price로 연결된다. 기존 `setProgress`를 활용한 작은 카메라 이동과 모형의 기존 유한 색 보간을 재사용한다.
2. phase 전환은 스크롤 위치에서 결정하므로 위로 되돌아가도 정확히 복원된다. 휠을 가로채거나 스크롤을 잠그거나 특정 시간 동안 기다리게 하지 않는다. 소개의 시각 요소만 제한 구간 sticky로 유지하고 체험에 도착하면 해제한다.
3. 장의 문구·범례·HTML 조건·가격·점수는 실제 예시 계산과 같은 selected ID를 사용한다. 사용자가 체험에서 고른 장소와 중요도는 소개로 돌아와도 반영된다. 스크롤 자체는 전역 상태를 수정하지 않는다.
4. 직접 조작 구간은 `#experience-city` 하나다. 슬라이더 입력→동일 state→색/요약/비교를 연결한다. 수동 카메라를 스크롤이 덮지 않는다. 담은 장소를 비교하는 행동은 비교 섹션으로 이어진다.
5. 중요 값은 opacity 0으로 숨기지 않는다. 장면 효과는 짧고 의미가 분명한 transform/색 변화로 제한한다. hover는 보조 정보이고 모바일·키보드는 HTML 대안이 있다.
6. reduced motion에서는 자동 카메라와 장면 보간을 멈춘다. 읽고 있는 장의 정보·범례는 즉시 갱신돼 내용이 빠지지 않는다. WebGL 미지원에서는 SVG와 동일 HTML 이야기가 남는다. JS 없이는 첫 정지 모형과 모든 장의 텍스트·비교 기본 값이 읽히고 비동작 조작은 비활성이다.

## 반응형과 브랜드

Pretendard, 밝은 paper/짙은 teal/가격 청록/점수 보라 유지. 새로운 테마·글꼴·라이브러리 없음. 데스크톱은 읽는 열 44%, 시각 무대 56%; 전체 체험·비교에서 좌우 틀을 깨고 넓어진다. 모바일은 첫 질문→도시→짧은 장 순으로 재배치하고 각 장을 읽을 때 도시가 내용을 가리지 않게 한다. 필요 시 모바일은 sticky를 풀고 짧은 in-flow 장면으로 전환한다. 320px에서도 본문 가로 overflow 금지, 비교표 내부만 가로 스크롤 가능. 제목은 두 줄 이하, 본문 16px 이상, 각주·UI 13px 이상, 버튼 44px 이상.

## 성공 판정

첫 화면에서 사용자의 질문과 ZIP이 무엇인지 읽힌다. 첫 네 장에서 같은 장소가 유지되고 색·설명·카메라가 장에 맞춰 함께 바뀐다. 한 번의 체험이 아래 선택 이유로 이어진다. 1440/768/390의 새 스크린샷을 직접 보고 위계·연결성·밀도·모바일 중첩을 수정한다. 계산·URL·결측·터치·reduced motion·그래픽 대체를 회귀 검사하고 동일 Pages에 배포 후 실제 공개 상태를 확인한다.

## 제작 검토 후 고정한 세부 계약

- storyPhase·카메라 progress만 스크롤에서 바뀐다. 제품 state/URL은 바뀌지 않는다. 슬라이더는 selected ID를 유지하고 그 장소의 점수와 색을 갱신한다.
- 유효한 공유 URL의 mode·weights·selected·saved가 모든 초기값보다 우선한다. URL에 mode가 없을 때만 체험 기본값 score를 쓴다. saved의 기본 A/B/C는 기존 parseState 기본값을 그대로 사용한다.
- 모바일은 도시와 본문에 겹치지 않는 영역을 예약하고, 낮은 화면에서는 sticky를 해제한다. 장의 조건·점수·비교 기본 값도 초기 HTML 본문에 남겨 정지 장면에서도 읽힌다.
- ‘실제’는 실거래를 의미하지 않는다. 모든 금액·점수·조건은 가상 예시다. 본인 제외·±5점·결측·월 환산식·표본 제한은 기존 함수를 그대로 쓴다.
- Impeccable은 보조 `animate` 지침에만 적용한다. 전체 아트 디렉션은 Taste 한 흐름이며, 제품 정본과 이 문서가 존재하므로 별도 전역 설정·init 인터뷰·두 번째 시각 체계를 만들지 않는다.

## DOM/연결 인터페이스

- 소개 root `#platform`; 각 장 `[data-story-step="price|conditions|criteria|value"]`, 각각 `#story-price`, `#story-conditions`, `#story-criteria`, `#story-value`. 시각 무대 `#story-stage` 안에 `#story-city` 한 개. 장별 보조 정보 `[data-story-panel="price|conditions|criteria|value"]`, 현재 장 링크 `[data-story-link]`. `#story-caption`, `#story-legend`(5개 i), `#hero-selection`은 소개의 현재 정보다.
- 소개 값은 반복 가능한 `[data-story-field="place|id|rent|deposit|area|slope|elevation|year|score|peer-count|unit|peers"]`로 렌더한다. 스크립트 전에는 A의 기본 값이 실제 HTML에 들어 있다. 반복 값이 서로 다른 선택 ID를 가리키지 않는다.
- 직접 체험은 `#experience-city` 하나. 기존 `weight-*`, `ratio-*`, `map-state-label`, `reset-weights`, `weights-note`, `selected-summary`, `save-selected`, `all-buildings`, `data-select`, `data-mode`, `mode-description`, `platform-legend`, `live-result`를 유지한다. 시점 조절은 `data-scene="experience"` 한 곳에만 두고 native details 안에 넣는다.
- 비교/공유는 `saved-count`, `saved-places`, `comparison-head`, `comparison-body`, `reset-demo`, `share-state`, `share-fallback`, `share-url`, `close-share`를 유지한다. 가격 비교 계산 `#value-result`는 체험의 가격 읽기 영역 안에 둔다. `#data`, `#toast`, `#reading-progress`와 skip link도 유지한다.
