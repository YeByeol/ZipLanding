# ZIP 서비스 소개 랜딩 디자인

작성: 2026-11-12 · 상태: **사용자 승인됨 — 이 디자인으로 제작·배포 진행**

## 요청과 기준

새 방향의 ZIP을 소개하는 한국어 랜딩 페이지를 만든다. 서비스 컨셉, 브랜드 로고, UX/UI, 스토리, 와이어프레임, 상호작용과 모션을 하나로 설계하고 GitHub Pages로 공개한다.

제품의 정본은 이웃 저장소 `ZipDev/docs/superpowers/specs/2026-11-12-zip-foundation-design.md`다. 기존 React 비용 비교 앱이나 VWorld 시안을 현재 제품 전체로 소개하지 않는다. 기존 ZipDev 저장소와 미커밋 작업은 수정하지 않는다.

이 문서에서 **사용자 확정**은 원래 요청과 제품 정본을, **제작자 선택**은 이번 랜딩을 위한 결정을 뜻한다. 사용자가 이 디자인으로 제작·배포 진행을 승인했다.

## 목적과 독자

- 독자: 살 곳을 찾으며 장소의 조건과 가격을 함께 판단하고 싶은 사람. 장기적으로 이동·투자·창업 분석에 관심 있는 독자도 받친다.
- 첫 화면에서 이해할 것: ZIP은 장소의 조건을 내 중요도로 종합하고, 비슷한 조건의 장소와 신고 가격을 비교하는 지도 플랫폼이다.
- 방문자가 할 일: 페이지 안의 예시 지도를 조작하고, 본인이 중시하는 조건에 따라 비교 결과가 달라지는 것을 확인한다.
- 성공 기준: 제품의 차이를 짧게 설명할 수 있고, 모바일에서도 슬라이더→지도→비교의 연결을 직접 체험할 수 있다.
- 범위 밖: 실제 부동산 검색·중개, 실시간 시세 제공, 로그인, 개인정보 수집, 결제, 실제 ZIP 앱의 완성·공개 배포.

## 접근 방법

1. **인터랙티브 도시 모형 — 채택 제안.** 같은 모형이 가격, 내 기준, 가격 대비로 바뀌고 방문자의 조작을 비교표까지 공유한다. 핵심 가치가 설명보다 행동으로 드러난다. 반응형·접근성·예시 계산을 함께 검증해야 한다.
2. **제품 영상 중심.** 몰입도는 높지만 영상 제작과 모바일 재생 부담이 있고, 방문자 자신의 기준이 결과를 바꾸는 체험은 약해진다.
3. **정적 기능 소개.** 가볍고 이해하기 쉽지만 사용자가 요청한 역동성과 동작 연결성을 충분히 보여주기 어렵다.

제작자 선택: 첫 번째를 주 흐름으로 삼는다. 불필요한 영상과 무거운 지도 SDK 대신 정적인 소개와 가벼운 도시 모형을 결합한다.

## 브랜드와 시각 방향

### 생각

**이 페이지에서는 ZIP의 ‘내 기준에 따라 다시 칠해지는 건물’이 직접 조작하는 도시 전시물이 된다.**

제품 고유의 재료: 관악구부터 시작, 건물 단위 선택, 가격·건물·지형, 가격을 점수에서 제외, 사용자 중요도, 세 곳 비교, 청록 가격·보라 점수, 신고 계약, 불명확한 거래의 묶음, 모르는 자료를 채우지 않는 원칙.

Taste 방향은 `borrowed-category`, seed `527163847`. 빌려오는 분야는 **건축 전시**다. 도시 모형을 크게 놓고, 설명과 조작을 함께 배치한다. 밝은 바탕과 짙은 청록색 면이 번갈아 나오며, 같은 크기의 기능 카드 나열을 피한다.

### 로고

- 이름과 워드마크: **ZIP**. 이름은 유지하고 새 SVG 원본을 제작한다.
- 심볼: 위아래 두 구획을 대각선으로 잇는 **Z**. 지도 구획·길·비교의 연결을 나타낸다. 지붕이나 위치 핀을 덧붙이지 않는다.
- 정방형 심볼, 가로 로고, 단색·반전형, favicon과 공유 이미지용 구성을 만든다.
- 24px에서 읽히는 형태, 의미 있는 대비, SVG 접근성 이름을 확인한다.

### 색과 글자

- 바탕 `#F6F7F4`, 본문 잉크 `#132D29`, 주 강조 청록 `#0A554D`.
- 제품 안의 가격은 정본의 청록 단계, 점수는 정본의 보라 단계로 유지한다. 보라는 점수라는 의미가 있는 제품 체험 부분에서만 쓴다.
- 지형은 절제한 모래색, 자료 없음은 중립색과 빗금으로 표현한다.
- 한글 본문과 제목은 한 계열의 고딕체. Pretendard를 우선 검토하고 배포 권한을 확인해 로컬 제공한다. 실패 시 시스템 한글 글꼴로 읽힌다.
- 제목은 모든 화면에서 최대 두 줄. 본문 16px 이상, 정보 각주 13px 이상. 기본 본문 대비 4.5:1 이상.
- 둥근 유리 패널, 배경 그라데이션, 장식용 배지, 가짜 고객 로고·후기·성과 수치를 넣지 않는다.

## 이야기와 전체 문구

메뉴: `플랫폼` · `내 기준` · `비교` · `데이터`. 주 행동 이름은 **예시로 체험하기**로 통일한다. 모든 메뉴와 버튼은 실제 섹션이나 동작에 연결한다.

### 첫인상

제목: **도시를 보는 / 나만의 기준**

본문: **장소의 조건을 내 중요도로 비교하고, 그 조건에 비춰 가격을 읽는 지도 플랫폼.**

행동: **예시로 체험하기** → 체험 섹션.

미디어: 밝은 지면 위의 입체 도시 모형. 선택 가능한 세 건물이 이어지는 이야기의 중심이다. 한쪽에는 현재 가격·조건을 보여주는 실제 체험 UI 일부가 놓인다.

### 자유 탐색

제목: **일단, 둘러보세요**

본문: **무엇부터 입력할지 고민하지 않아도 됩니다. 궁금한 건물을 고르고 가격, 건물, 지형을 함께 살펴보세요.**

근거: 가격·건물·지형 탭과 선택 건물의 조건 표시. 입력 없이 시작하는 제품 방향을 보여준다.

### 내 기준 체험

제목: **기준을 바꾸면 / 도시도 달라집니다**

본문: **완만한 경사, 낮은 고도, 건물 연식. 중요도를 조절하면 건물의 색과 비교 결과가 함께 바뀝니다.**

근거: 실제 작동하는 세 슬라이더와 지도, 조건별 값, 점수. `모두 같은 중요도` 초기화 버튼.

체험 표시: **설명용 예시 데이터 · 실제 지역 가격이 아닙니다.** 이 문구는 체험과 비교 결과를 보는 동안 확인할 수 있게 둔다. 실제 주소나 공공 건물 도형을 넣지 않는다.

### 가격과 조건

제목: **조건 옆에 / 가격을 놓습니다**

본문: **점수가 비슷한 장소의 가격을 나란히 보세요. 어떤 조건을 얻고, 얼마를 더 쓰는지 살펴볼 수 있습니다.**

근거: `가격 / 내 기준 / 가격 대비` 전환. 실제 금액, 비교 지표와 계산 근거를 함께 보여준다. 설명용 예시는 실제 시장의 저평가·고평가 판정으로 쓰지 않는다.

### 장소 비교

제목: **세 곳 사이, / 선택의 이유**

본문: **정답을 대신 정하지 않습니다. 담은 장소의 가격과 조건을 나란히 놓고, 내가 중요하게 보는 차이를 확인하세요.**

근거: A·B·C 담기, 제거와 선택 강조, 조건별 값, 같은 기준의 비교표, 현재 체험 상태 링크 복사.

### 근거와 범위

제목: **숫자에 / 근거를 붙입니다**

본문: **어디서 왔는지, 언제의 값인지, 얼마나 모였는지. 모르는 값은 모른다고 표시합니다.**

내용:

- **신고 계약**: 현재 매물이나 호가가 아닙니다. 관리비는 포함하지 않습니다.
- **추정한 조건**: 지형과 경사는 계산 방법과 한계를 함께 표시합니다.
- **비슷한 건물 묶음**: 개별 위치가 공개되지 않는 거래를 특정 건물의 확정 가격처럼 표시하지 않습니다.
- **자료 없음**: 0이나 나쁜 조건으로 바꾸지 않습니다.

짧은 FAQ는 ‘실제 서비스를 이용할 수 있나요?’, ‘가격은 현재 매물인가요?’, ‘무엇부터 제공하나요?’를 다룬다. 답은 각각 ‘현재는 개발 중인 서비스의 소개와 예시 체험’, ‘신고 계약을 바탕으로 하는 방향이며 이 페이지는 가상 예시’, ‘관악의 가격·건물·지형부터, 나머지는 확장 예정’으로 명확히 쓴다.

### 마무리

제목: **관악에서 시작하는 / 새로운 장소 읽기**

본문: **첫 범위는 가격·건물·지형입니다. 교통, 생활시설, 인구와 상권 등은 이후 같은 지도에 더할 계획입니다.**

행동: **예시로 체험하기**. 큰 ZIP 워드마크로 닫고, 실제 공개 후 연결되는 GitHub 소스 링크와 저작·예시 표시를 둔다. 연락처나 외부 서비스 주소를 임의로 만들지 않는다.

### 모바일

```text
ZIP                         [예시 체험]
도시를 보는
나만의 기준
서비스 설명 + [예시로 체험하기]
[화면 폭을 쓰는 도시 모형]

[한 구간 한 설명 → 바로 아래 해당 시각화]
[가격·건물·지형 탭]
[현재 지도 / 선택한 곳]
[세 중요도 조절: 터치·키보드 가능]
[A·B·C 비교: 레이블 열 + 필요하면 가로 스크롤]
[자료의 의미 / FAQ / 마지막 행동 / ZIP]
```

스크롤을 가로채지 않는다. 한 섹션을 여러 화면 동안 강제로 고정하지 않는다. 모바일의 필수 정보와 조작은 hover 없이 노출한다. 가로 스크롤은 비교표 영역 안에서만 허용한다.

## 상호작용 계약

- 한 개의 체험 상태를 지도, 선택 건물, 슬라이더, 비교표가 공유한다. 섹션별로 숫자가 따로 움직이지 않는다.
- 직접 만든 가상 건물 약 18~30개와 비교용 기준값을 사용한다. 핵심 후보는 A·B·C다. 정확한 예시 값은 제작자가 일관되게 정하고 데이터 파일에 보관한다.
- 조건은 경사·고도·연식 세 가지다. 가격은 점수에 넣지 않는다. 처음에는 동일 중요도다.
- 중요도는 0~100 입력을 합이 1이 되게 정규화한다. 모두 0이면 동일 중요도로 계산하고 그 사실을 알린다. 점수는 예시 데이터 안에서 계산하며 실제 관악 순위라고 하지 않는다.
- 결측 조건은 계산에서 빼고 빠진 것을 표시한다. 가중치·단위·조건별 실제 예시 값으로 결과를 설명한다.
- 가격 비교는 면적당 월 환산값을 사용하고 연 5% 가정을 표시한다. 실제 금액도 함께 둔다. 예시 기준 집합과 비교 개수를 공개한다.
- 작은 예시 집합을 실제 시장 표본처럼 보이게 하지 않는다. 표본 부족 시 퍼센트 요약 대신 대상의 예시 가격을 나열한다.
- 건물 선택은 지도 클릭뿐 아니라 같은 이름의 HTML 버튼으로 가능하다. 선택과 담기는 별개다. 최대 세 곳, 중복 금지, 제거와 초기화 제공.
- 공유는 URL에 체험 상태만 담고 Clipboard API 실패 시 수동 복사 입력을 제공한다. 개인정보와 사용자 입력 텍스트를 받지 않는다.
- 메뉴 이동, 탭, 슬라이더, 담기, 제거, 공유, 초기화, FAQ 동작을 전부 연결한다. 무의미한 클릭 요소를 만들지 않는다.
- 자바스크립트가 없으면 소개·시각 자료·기본 예시 비교를 읽을 수 있다. 체험 기능은 스크립트가 필요하다고 안내한다.

## 그림과 모션

- 로고와 도시 모형은 이번 페이지를 위해 만든 벡터·코드 기반 자산이다. 실제 도시·현재 앱 화면으로 소개하지 않는다.
- 네 가지 장면(전체 도시, 조건별 재색칠, 선택 장소 확대, 세 곳 비교)을 일관된 시각 언어로 만들고, 정지 그림·공유 이미지·비동작 대체 이미지로도 내보낸다. 네 이미지가 같은 내용의 장식 반복이 되지 않게 한다.
- 제공되지 않은 실제 제품 화면, 임의의 해외 건축 사진, 생성한 실사 지도를 제품 증거로 사용하지 않는다. 실제 자료나 사진을 추가한다면 출처와 이용 조건을 먼저 확인하고 표기한다.
- 시그니처: 도시 모형이 한 방향으로 열리고 안정된 뒤 사용자의 기준에 맞춰 색이 바뀐다. 첫 동작은 짧고 한 번만 실행한다.
- 스크롤 진입은 텍스트와 그림이 60~90ms 차이로 16~24px 정도 등장한다. 모든 요소가 똑같이 떠다니지 않는다.
- 버튼·탭·선택 건물은 눌림·hover·focus 피드백을 준다. 자동 카메라 이동이 사용자의 조작을 덮지 않는다.
- 움직임 줄이기에서는 이동·회전·자동 재생을 없애고 즉시 결과를 표시한다. 내용은 스크립트 실패 시에도 숨겨지지 않는다.

## 구현과 배포 선택

제작자 선택: 이 작업은 독립 폴더 `ZipLanding`의 정적 HTML/CSS/JavaScript로 만든다. 랜딩과 브라우저 내부 체험에 React나 지도 SDK, 서버는 필요하지 않다. 필요한 경우 정적 자산 내보내기용 작은 개발 스크립트만 둔다.

GitHub 확인: 인증 계정 `YeByeol`, `YeByeol/ZipLanding` 저장소는 아직 없다. 디자인 승인 후 별도의 공개 저장소를 만들고 GitHub Pages Actions로 배포한다. 예상 주소는 `https://yebyeol.github.io/ZipLanding/`이며, 실제 성공 후 확정 URL을 보고한다. 저장소 생성·코드 공개·배포는 사용자의 원래 요청 범위다.

배포 대상에는 랜딩 소스와 필요한 자산만 포함한다. ZipDev 원자료, 환경 파일, 키, 비공개 문서, 가공한 공공 건물 자료, 로컬 실행 기록은 포함하지 않는다. 자산 경로는 프로젝트 Pages 하위 경로에서도 작동하게 작성한다. 미리보기와 공개 페이지에서 같은 상호작용을 확인한다.

## 검증과 완료 기준

- 핵심 예시 계산: 슬라이더 변경, 모두 0, 결측, 비교 개수·가격 산식, 공유 상태 복원, 담기 제한을 작은 의미 있는 테스트로 확인한다.
- UX: 메뉴→체험→조건 변경→건물 선택→담기→비교→공유→초기화를 실제 브라우저에서 수행한다.
- 화면: 1440·768·390px와 좁은 모바일에서 제목 두 줄, 정보 계층, 지도·본문 대비, overflow와 터치 목표를 확인한다.
- 접근성: 키보드만으로 사용, 보이는 focus, 입력 이름, 결과 안내, 색 외 표시, reduced-motion, 스크립트 없는 읽기 경로를 확인한다.
- 시각 품질: Taste 소스 검사·브라우저 검사, 모든 화면 크기의 스크린샷을 직접 보고 수정한다. 브랜드 점수 보라색은 의미가 정해진 예외로 기록한다.
- 공개: GitHub Actions 성공, 실제 Pages 응답, 자산 404 없음, HTTPS, 모바일과 데스크톱 동작을 확인하고 배포 주소를 전달한다.

이번 디자인 승인에 필요한 것은 위 컨셉·시각 방향·체험 범위다. 구체적인 여백, 구현 함수, 예시 값, 화면별 세부 모션 조정은 제작자가 결정한다.
