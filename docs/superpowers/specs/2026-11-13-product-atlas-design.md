# ZIP product atlas redesign

## Intent and authority

The user asks for an implementation and publication upgrade grounded in the actively developed sibling ZipDev repository, plus external free 3D/design research. Existing permission to redesign and deploy persists. ZipDev is read-only; its current dirty work is preserved. This is a product-backed redesign of ZipLanding, not a request to change the app or claim it has launched.

## Product truth

Use the current foundation design, app code at 98c05b3, and the two current audit reports. ZIP is a place-comparison map beginning in Gwanak. Price/building/terrain, priorities and mandatory constraints, same-type price context, three-place comparison, a rolling six-month price interval, and evidence/depth views are implemented in the development app. Transit/life/population-commerce/environment are planned. Dedicated product mobile work and user acceptance remain incomplete. No live-listing, real-time, AI valuation, nationwide coverage or completed-launch claim.

## Approaches and chosen composition

Considered: rebuild the whole landing as a live MapLibre client (duplicates a developing app and requires a production data endpoint); retain only the fictional architectural film (cannot demonstrate the now broader product); combine a shorter continuous 3D explanation with an actual-product scroll atlas (chosen by the implementer within the user's redesign brief). Existing Three and shared scroll clock remain; no extra animation runtime is required.

Taste: page-is-the-object, seed161657969, keep palette/type. The object is the map atlas itself, not decorative stationery. One hero redraw was necessary because the first blueprint puts an opaque programme card over imagery, directly conflicting with the user's no-text-mask requirement. The replacement's split proportions inform the map/copy relationship; fake stripes, a room photograph and hospitality ornament have no ZIP source and are omitted. Product captures replace generic imagery. No fabricated metrics, testimonials, logos or launch claims.

Keep the existing central A architecture and materials, increase neighborhood specificity with diverse block silhouettes, low/mid-rise context, readable streets/crossings and shared greenery. Use locally pinned Three and its official addons; no unverified stock GLB/HDR/license dependency. The same records drive SVG fallback. Avoid adding colored base plates. Geometry remains explicitly illustrative, not a model of Gwanak or observed terrain.

## Implementation and validation constraints

Brand palette, font, logo and example arithmetic remain. Every new external-facing asset must be local and attributed as appropriate. The optional example's input/query/selection/focus restoration stays intact. Use the existing motion scheduler for the product atlas, including reduced motion and hidden-tab behavior; no continuous idle rendering. No JS and blocked WebGL must retain complete reading content. Desktop/tablet/mobile, short height and enlarged type need collision checks. Inspect intermediate transitions, not just holds. Deploy only after checks, then verify public versioned assets and actual browser states. A dedicated browser profile is used for app captures; the user's working app/tab is not changed.
