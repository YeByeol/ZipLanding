# ZIP 4.2 제품 소개 재설계 검증

2026-11-13. ZipDev의 현재 구현·기획은 읽기 전용으로 확인하고 ZipLanding만 변경했다. 기존 승인 범위에 따라 구현 후 GitHub Pages에 공개한다.

## 반영한 변화

- 최신 ZipDev foundation 설계와 실제 구현을 별도 조사한 뒤, 관악구의 신고 가격·건물·지형을 읽는 제품으로 첫 설명과 전체 카피를 맞췄다. 제품의 현재 구현, 후속 계획, 소개용 가상 예시를 구분했다.
- 기존 브랜드·중앙 건물·공통 스크롤 clock을 유지했다. 주변 여섯 건물의 형태·높이·옥상과 도로·횡단보도·가로수를 다시 구성했다. 13 draw calls / 406 instances / 6,504 triangles. 정적 SVG도 같은 설계에서 다시 생성했다.
- 3D 소개의 전체 이동 길이를 1080svh에서 730svh로 줄이고, 실제 개발 화면 네 단계와 개발 방향·마무리를 연결했다. 실제 화면은 같은 장소와 카메라를 유지한다.
- 제품 화면끼리 오래 혼합되면 숫자가 이중으로 보이는 문제를 독립 검토에서 발견했다. 이전 화면을 불투명하게 유지한 채 새 화면을 220ms 안에 완전히 표시한다. 스크롤을 멈춰도 중간 혼합 상태가 남지 않는다.
- 모바일 상세 화면에 원본 비율을 명시해 지연 로드 때 공간을 미리 확보했다. 작은 그래프의 범례·집계 기간·표시 수치는 HTML 본문에도 옮겼다.
- 모듈·vendor·모듈 에셋은 불변 runtime 디렉터리, CSS·HTML 이미지·글꼴은 콘텐츠 버전 URL로 배포한다. 이미 열려 있는 옛 HTML을 강제로 갱신하는 기능은 아니다.

## 확인 결과

- Node 테스트 **97/97 통과**, 전체 문법 검사와 `git diff --check` 통과. 예시 점수·가격 계산·자료 없음·자원 소유·정적 그림과 기존 동작 테스트 포함.
- 제품 전환의 정지 상태 혼합을 탐지하는 테스트 실패를 먼저 확인하고 수정 후 통과했다.
- 1440×900, 768×1024, 390×844, 375×667에서 여덟 장면과 네 제품 단계를 점검했다. 48개 상태 기록에서 가로 넘침 0. 추가 320×844 첫 장면도 가로 넘침 0.
- 텍스트 컨테이너의 배경은 투명. 주요 장면의 제목·정보 영역과 모델, 하단 탐색 영역을 스크린샷으로 확인했다. Three canvas는 하나다.
- 제품 소개의 11개 정방향·역방향·중간 위치를 이동한 뒤 300ms 후 확인: 현재 화면 opacity 1, 활성 링크 영역 하나, 아래 화면도 완전히 그려져 있다.
- 1440/768/390 자동 브라우저 검사에서 깨진 이미지·콘솔 오류·가로 넘침 0. 최종 크기 변경 이후 13px 미만 본문 경고도 없어졌다.
- 375×667에서 모듈 요청을 차단한 경우 여덟 설명 장면과 네 제품 상세 이미지가 일반 문서 흐름으로 보인다. 이미지 폭·높이가 예약되어 있다.
- 움직임 줄이기 설정에서 실행 중 애니메이션 0, 제품 화면 scale 1. 3D vendor 요청을 차단한 경우 canvas 0, SVG 대체 그림과 전체 설명이 보인다. 실제 모든 GPU의 WebGL 실패 조건을 재현했다는 뜻은 아니다.
- 24개 장소 체험창 열기·닫기, 닫기 버튼 초기 초점, 원래 스크롤 위치와 여는 버튼 초점 복귀 확인.
- 독립 검토자가 제품 설명의 현재/예정 구분, 6개월/12개월 기간, 비실시간·비AI 조건과 최종 시각 수정 내용을 확인했고 남은 차단 이슈는 보고하지 않았다.
- 독립 임시 빌드에서 `/ZipLanding/` 기준 URL 62개(고유 43), 도달 가능한 ESM 19개와 import 38개, 제품 이미지 8개 경로를 확인했다. 이미지 누락 시 HTML 변경 전에 실패한다. 이후 최종 수정본도 별도 임시 디렉터리로 빌드해 브라우저에서 실제 해시 runtime·제품 모듈·3D canvas 로딩을 확인했다.

## 디자인 검토의 범위

Taste v2의 `page-is-the-object` 방향을 기존 팔레트·글꼴 유지 조건으로 적용했다. 제목·도시·가격과 근거의 역할을 분리하고 실제 제품 이미지 네 장을 사용했다. 전문 디자이너의 심사나 수상 등급을 주장하지 않는다.

자동 검사 예외는 다음처럼 근거를 남겼다.

- `empty-screens`: DOM 이미지 측정에 잡히지 않는 전체 화면 WebGL 모형이 있는 구간이다. 개별 장면 실제 캡처로 구성과 모델의 면적을 검토하고, 기존 길이를 단축했다.
- `pinned-over-picture`: 캔버스 사각형은 화면 전체지만 실물 모델과 텍스트는 서로 다른 구역에 있다. 텍스트 배경을 제거한 상태에서 장면별·모바일 캡처로 확인했다.
- `eyebrow`: 촬영 날짜와 후속 계획 상태를 표시하는 실제 캡션이다. 장식용 제목 라벨이 아니므로 삭제하지 않았다.
- `no-footage`: 별도 영상 대신 실제 Three 장면이 공통 스크롤 진행값으로 움직이며, 별도 가상 장소 체험도 작동한다.

최종 자동 결과는 예외 적용 후 0 FAIL / 1 WARN. 남은 글자 크기 수 경고는 다양한 숫자·단위와 반응형 유동 크기를 포함한 측정이다. 실제 본문과 캡션의 가독성을 우선했다. 이 숫자는 미적 품질 점수가 아니다.

시각 기록은 로컬 `qa/product-rebuild/`에 보관한다. 실제 화면 출처와 가공 범위는 [캡처 기록](research/2026-11-13-product-captures.md), 외부 조사와 선택 근거는 [레퍼런스 연구](research/2026-11-13-landing-reference-study.md)에 있다.

## 남은 제품 범위

이 페이지는 정적 소개와 가상 체험이다. 실제 관악구 앱의 공개 운영 URL을 제공하지 않는다. 전용 모바일 앱 UX, 후속 자료군, 최종 제품 사용자 검수는 개발 계획의 일부다. 실기기 Safari 전 기종·GPU별 성능은 이번 검증 범위에 포함되지 않는다.
